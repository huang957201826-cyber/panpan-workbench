## 三、重点一：真实长宽比为什么没做到

### 3.1 三条链路，三套算法

| 对象 | 算法 | 结果 |
|---|---|---|
| 画布任务节点 | `getTaskNodeSize`：先看 `task.canvas.w/h`（用户拖过就永久锁定），否则用 `actualParams.size ?? params.size` | 与**真实图片**无关 |
| 画布素材节点 | `probe.naturalWidth/Height` → `fitCanvasImageNodeSize` | 真实比例 ✅ |
| 九宫格卡片 | CSS `aspect-[16/9]` + `object-cover` | 固定 16:9，且**裁切** |

### 3.2 根因（可复现）

1. 生成时 `size = auto` 或 16:9，节点先按请求尺寸开框（`NODE_WIDTH=360`，高度按比例）。
2. **用户只要拖动一次节点**，`CanvasBoard.onMove → updateTaskCanvas(id, {x,y,w:width,h:height})` 就把当时的 w/h 写进 `task.canvas`。
3. 图片回来后 `actualParams.size` 变成真实值（如 `1312×1199`），但 `getTaskNodeSize` 第一优先级是 `task.canvas.w/h` → **永远不再重算**。
4. 于是 1.09:1 的图被放进 2:1 的框，`object-contain` 只能左右留白。

数据库实证（真实数据）：

```
任务「生成一个橘子」  params.size=auto  actualParams.size=1312x1199
  canvas = { w: 457.93, h: 228.97 }      → 2.00 : 1（错误）
  images  = 1312 x 1199                  → 1.09 : 1（真实）
任务「生成一个红色圆形」canvas = 360 x 360 → 1.00 : 1  ✅（没被拖过，按 actual 算的）
```

### 3.3 修复口径（待你确认后再动）

- 节点尺寸优先级改为：**真实图片像素 > actualParams.size > params.size > 4:3 占位**。
- `task.canvas` 增加"是否用户手动改过"标记：没改过 → 图片就绪时自动校正比例；改过 → 保留用户尺寸（但提供"还原真实比例"右键项）。
- 九宫格：卡片统一尺寸可以保留，但图片改 `object-contain` + 中性底色（不裁切）；或按真实比例渲染（瀑布流），二选一，需和"九宫格要整齐"权衡。
- 素材节点已经是正确实现，可作为参照实现复用。

## 四、重点二：九宫格 vs 无限画布的差异全景

### 4.1 结构差异

| 维度 | 九宫格 | 无限画布 | 差异性质 |
|---|---|---|---|
| 卡片单位 | **每张输出图一张卡**（多输出 = 多卡） | **每个任务一个节点**（多输出有"N 张"角标 + 菜单） | 结构不同 |
| 生成中/失败 | 不出现 | 有占位与红 X | **能力缺失** |
| 参考图素材 | 不出现（只在画布/输入台） | 独立素材节点，带"图N" | **能力缺失** |
| 排列 | 固定网格 + 分页 | 自由坐标 | 合理 |
| 图片适配 | `object-cover` 裁切 | `object-contain` 留白 | 策略冲突 |
| 尺寸信息 | 左下角常驻 `resolution` 胶囊 | 只有选中时左下角显示 `size`（且被手柄压住） | 不一致 |
| 收藏 | 无单卡收藏 | 无单节点收藏（只有批量） | 两端都缺 |
| 头部 | "九宫格历史卡片" 标题行（会滚走） | 无标题，只有浮动工具 | 结构不同 |

### 4.2 操作项逐项对照（以九宫格右上角为基准）

**九宫格右上角现有样式（基准）**：`h-6`、圆角 `rounded-lg`、`bg-black/80` 玻璃底、hover 纯黑、图标 12px Lucide（线宽 1.5）、间距 4px、hover 时 70% → 100% 透明度。唯一带文字的是"设为垫图"（图标 + 文字）。

| 功能 | 九宫格 | 无限画布（任务节点） | 无限画布（素材节点） | 需要对齐的点 |
|---|---|---|---|---|
| 设为参考图 | ① 右上角，**图标 + 文字**"设为垫图" | ② 节点上方横条，**纯文字**"设为参考图"；右键也有 | ③ 右键"设为参考图" | 文案三种（垫图/参考图/引用）；画布无右上角入口 |
| 复用参数 | 右上角 **纯图标**（RotateCcw） | 上方横条 **纯文字**"复用参数" | 无 | 必须统一为图标 |
| 下载 | 右上角 **纯图标**（Download），单张 | 右上角 **字符"↓"** 圆形，多输出有菜单 | 右上角 **字符"↓"** | 字符换图标；位置形状统一；多输出两端一致 |
| 删除 | ❌ 无 | 上方横条 **纯文字**"删除"（红） | 右键"删除素材" | 九宫格缺入口；画布危险操作暴露在第一层 |
| 复制提示词 | 右上角 **纯图标**（Copy） | ❌ 无（只有 hover 卡片显示提示词，且该卡片要删） | 无 | 画布缺 |
| 送入主画布 | 右上角 **纯图标**（Layers） | ❌ 无（本就在画布） | 无 | 合理差异 |
| 保存为技能 | ❌ 无 | 上方横条 **纯文字** | 无 | 九宫格缺 |
| 编辑输出图 | ❌ 无 | 上方横条 **纯文字** | 无 | 九宫格缺 |
| 重新生成 | ❌ 无 | 上方横条 **纯文字** | 无 | 九宫格缺 |
| 详情 | 点卡片直接开检视 | 上方横条"详情" + 双击打开 | 双击设为参考图 | 交互模型不同 |

**结论**：不是"图标没统一"这么简单，是**两套操作体系**：
- 九宫格 = 右上角 5 枚图标（hover 出现、图标为主）
- 画布 = 选中后节点上方一条 7 个文字按钮的长条（还有一份右键菜单重复同一批动作）

### 4.3 建议的统一规范（待确认）

1. **位置统一**：两视图都把高频操作放**卡片/节点右上角**，24px 高、`rounded-lg`、`bg-black/80` 玻璃底、hover 纯黑、图标 12–13px、间距 4px。
2. **第一层只放 4 个**（都能用图标自解释）：
   `设为参考图`（# 或 ImagePlus）、`复用参数`（RotateCcw）、`下载`（Download）、`更多`（MoreHorizontal）。
3. **其余全部收进"更多"菜单**：复制提示词、保存为技能、编辑输出图、重新生成、详情、送入主画布（按视图显隐）、删除（红色，末尾，二次确认）。
4. **唯一允许"图标 + 文字"的**：`设为参考图`（因为语义重、图标歧义大）—— 与九宫格现状一致，画布跟随九宫格。
5. **术语统一**：全部叫"参考图"，"垫图"只作为说明文字出现。
6. **触发统一**：hover 显示（透明度 70% → 100%），选中常驻；不要一个 hover 一个"选中才出"。
7. **删除统一**：两端都进"更多"菜单 + 二次确认 + 回收站快照；不放在第一层。
8. **多输出统一**：两端都提供"下载第 N 张"菜单；文件名后缀一致（现在九宫格恒为 `-1`）。
9. **图标库统一**：全部改用 Lucide（线宽 1.5），去掉"↓"这类字符图标。

### 10.1 P4 工程决策（与 SKILL-HUB-SPEC 的偏差，需知悉）

1. **分类枚举只在视图层归并**：`skillCategoryOf` 把旧数据的自由文本归入「其他」，持久化里的原值一字不改。曾考虑写进 `normalizePromptSkill` 做迁移，会破坏「旧数据原样读回」的既有不变量，故改为纯派生。
2. **顶栏 Tab 是范围轴（全部 / 已收藏 / 已置顶 / 常用），不是第二个分类轴**：数据模型只有一个 `category`，做「分类双轴」必须凭空造第二个维度。现在是「左侧分类 → 顶栏范围」两个真实可叠加的轴，都带计数，分段控件形态与参考一致。
3. **负向提示词不进生成链路**：全项目没有 negative 字段，新增供应商参数会牵动 API 适配、表单、导出与 ZIP 备份，超出 P4 范围。现在只在技能库内合成后拼到 prompt 尾部（`Negative prompt: …`）。若以后要独立透传，需单独排期。
4. **骨架态由 persist hydration 驱动**，不是人为 setTimeout；卡片描述复用 prompt 原文两行截断，不新增 description 字段。
5. 卡片操作条复用 `src/ui` 的 Button / Chip / Card，没有出现 UI-35 担心的第三套实现。
