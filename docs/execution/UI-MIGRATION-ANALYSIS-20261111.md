## 0. 结论摘要

1. 参考工程是**纯前端 mock**：没有 Tauri、没有真实生图、没有 Zustand 持久化。能复用的是组件版式、设计 Token、交互外观；不能复用的是它的状态管理、mock 数据、ComfyUI、桌面窗口模拟。
2. 两份交接文档存在明显冲突（抽屉 230 vs 256、13px 上限 vs 44px 大标语、严禁大胶囊 vs 大量 `rounded-full`）。按你的要求，**以 `HANDOVER_UI_SYSTEM.md` 为准**，`HANDOVER.md` 只作为组件职责参考。
3. 参考工程用 **Tailwind CSS 4**，当前项目是 **Tailwind CSS 3.4**。`@theme`、`@custom-variant` 不能直接复制，必须转成 CSS 变量 + `tailwind.config.js` 扩展。
4. “1:1 像素级”建议限定为：**外壳、导航、首页、画布悬浮层、输入岛、设计 Token** 做到尺寸/颜色/阴影一致；设置、技能、详情等业务界面按同一语言重绘，不为了像素牺牲现有功能。
5. 参考工程的“工作流”是 ComfyUI 节点画布，与你上一轮要求的“旧版工作流截图”冲突。**工作流仍按 N16 还原旧版，不移植 ComfyUI。**
6. 你要求“Zustand 数据存储不动”，但 N17（删除提示词库）、N18（内置技能可编辑）、N20（技能多图）都需要数据层改动。建议拆成两批：
   - **纯 UI 批**：不动 Store 结构，只做视觉与布局；
   - **技能数据批**：单独做迁移/字段扩展，带备份与回滚。
7. 建议分两个版本落地，降低一次性重写风险：
   - **1.1.0**：Token、外壳、首页、画布 Chrome、输入岛；
   - **1.2.0**：技能合并/多图、设置/详情/九宫格、工作流旧版、像素收口。

### 2.4 字号

参考是英文界面：10.5–15px，首页 44px。中文最小可读性更高，建议：

- 应用内保留 6 档：10 / 12 / 13 / 14 / 15 / 20；
- 首页大标语单独一档：40–44px；
- 不把 10.5px 强行用于中文正文，最低 11–12px；
- 数字/快捷键用 mono 10–11px。

### 2.5 字体

参考用 `Geist` + `Space Grotesk`，当前项目用 Noto Sans SC + Maple Mono。直接换字体会影响中文显示与安装包体积。

建议：

- 中文继续 Noto Sans SC；
- 拉丁字母/数字可引入 Geist 子集（OFL 协议），只用于标题与数字；
- 若不引入，使用系统 `Segoe UI` + 现有中文字体，视觉上接近 90%，不是严格 1:1。

### 2.6 Tailwind 3 适配

参考的 `@theme` 不能直接用。落地方式：

1. 在 `src/index.css` 的 `:root` / `.dark` 增加：
   - `--bg-app`、`--surface-tile`、`--accent-strong`、`--tag-bg`、`--tag-text`；
   - `--radius-tile: 16px`、`--radius-float: 24px`；
   - `--shadow-soft-card`、`--shadow-soft-float`。
2. 在 `tailwind.config.js` 扩展 `colors`、`borderRadius`、`boxShadow`、`fontSize`。
3. 新组件只用 Token，不再写 `bg-[#f3f4f8]`、`text-[10px]` 这类任意值。
4. 旧组件按批次替换，不一次性全改。

## 5. 冲突与需要你拍板的事项

### 5.1 严格 1:1 与“Zustand 不动”的冲突

N17/N18/N20 需要数据层改动：

| 需求 | 纯 UI 能否做到 | 需要的数据改动 |
|---|---|---|
| 删除提示词库 | 可以隐藏入口，但旧数据仍在 | 要么保留 PromptSkill store，要么迁移到 Skill |
| 内置技能可编辑 | 可以用“复制为我的技能”实现 | 若要直接改内置，需要扩展 `builtinOverrides` |
| 技能多图 | 可以只做展示层 | 要持久化多图，需要给 `Skill` 加可选字段 |

建议：

- **1.1.0 纯 UI 批**：只隐藏提示词库入口、统一视觉；内置编辑先用“复制为我的技能”；技能多图先不做持久化。
- **1.2.0 数据批**：再做 `PromptSkill → Skill` 迁移、`builtinOverrides` 扩展、`referenceImageIds` 字段，带备份/回滚。
- 这样符合“底层存储不动”的约束，也不会把 UI 重做和数据迁移混在一起。

### 5.2 首页默认行为

`HANDOVER_UI_SYSTEM` 要求默认首页、首页隐藏二级抽屉。当前默认是 `projects`。需要确认：

- 每次启动都回首页，还是记住上次页面？
- 首页输入后直接生成并切到画布，还是只填入提示词？
- 首页大标语用“空间设计”文案，还是改成通用生图文案？

### 5.3 顶栏与 C-Logo

文档一句话写“顶栏单 C-Logo”，但验收清单写“只有左侧 Rail 最顶端一个 C-Logo，顶栏左侧无品牌文字”。建议按验收清单：

- C-Logo 只放 Rail 顶部；
- 顶栏 36px 全透明，只留拖拽区和窗口三键；
- 原来的“应用/编辑”菜单动作移到二级抽屉/底栏更多/快捷键；
- 项目名移到抽屉标题或窗口标题，不在顶栏中间显示。

### 5.4 字体

是否引入 Geist / Space Grotesk 字体文件？

- 引入：更接近参考，但增加安装包体积与字体许可清单；
- 不引入：用系统字体，视觉接近但非严格 1:1。

### 5.5 工作流

参考工程是 ComfyUI 节点画布；你上一轮要求旧版截图。建议：

- 工作流按 N16 旧版截图还原；
- 不移植 ComfyUI；
- 等以后真正做节点工作流时再单独开阶段。

### 5.6 参考工程自身的重复

参考工程技能页同时有“抽屉分类”和“顶部分类 Tab”。这会造成新的二级/三级重复。建议只保留抽屉分类，内容区只放搜索/模型筛选/新增，不复制顶部重复 Tab。

## 7. 风险清单

| 风险 | 影响 | 处理 |
|---|---|---|
| Tailwind 3 vs 4 | Token 直接复制会失效 | 先做 CSS 变量适配层 |
| `zoom` / 最小点击区覆盖 | 28px 胶囊被放大 | 新组件用独立 Token，不改全局覆盖 |
| 大面积 `backdrop-blur` | 画布拖动掉帧 | 只在小浮层用 |
| 中文字体 vs Geist | 字号/行高偏差 | 中文单独调 11–14px |
| 顶栏去菜单 | 新建/复制配置入口丢失 | 先迁移动作，再删菜单 |
| 首页默认 | 改变启动路径 | 可配置/记住上次页面 |
| 技能数据迁移 | 旧提示词丢失 | 单独批次 + 备份 + 回滚 |
| 工作流参考冲突 | 做成 ComfyUI 违背 N16 | 明确不移植 |
| 参考工程 mock | 误把假数据接进生产 | 只取 UI，不取 data/App 状态 |

## 8. 建议的版本与批次

| 版本 | 内容 | 风险 |
|---|---|---|
| **1.1.0** | U0–U4：Token、外壳、首页、画布 Chrome、输入岛 | 中 |
| **1.2.0** | U5–U7：技能视觉、设置/详情/九宫格、工作流旧版 | 中高 |
| **1.2.x** | 技能数据迁移、多图持久化、内置编辑覆盖层 | 高，单独备份 |

不建议把 U0–U8 一次性塞进一个版本；UI 重塑最容易出现“局部都对、整体不一致”，必须分批截图验收。
