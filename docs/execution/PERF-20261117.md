# 工作流拖拽性能（2026-11-17）

## 测法

- dev 构建（`npm run dev`），`ComfyWorkflowView` 内置 DEV 专用帧率 HUD：拖拽节点期间用 `requestAnimationFrame` 记录帧间隔，松手后显示平均 / 最差 / 帧数。
- `node scripts/perf-drag.mjs` 用 Playwright 驱动 Edge：进入工作流页，按住第一个节点标题拖动 3 秒（120 步），读取 HUD 文本。

## 基线（优化前）

```
DRAG_PERF avg 13.3ms · max 26.7ms · 522f
```

## 优化后

```
DRAG_PERF avg 13.4ms · max 26.7ms · 392f
```

两次都在 60fps 目标内（平均 ≤16.7ms、最差 ≤33ms）。这台机器上 rAF 层面看不出差异，但结构性问题已经消除：拖拽期间不再每像素写 React state，模糊合成与点阵动画也不再参与拖拽。

## 改了什么

| 项 | 改动 |
|---|---|
| A. 拖拽不写 state | `pointermove` 只改被拖节点的 `transform: translate3d()`，`pointerup` 时一次性 `setNodes` 落位 |
| B. 节点 memo | **未做**：A 之后拖拽期间已无整树重渲染；拆 500 行节点卡片的风险高于收益，记录为后续项 |
| C. 点阵暂停 | `InteractiveDotGrid` 新增 `paused`，拖拽/平移时停 rAF |
| D. 拖拽关模糊 | 根节点 `data-dragging` + `index.css` 里 `[data-dragging] * { backdrop-filter: none }` |

## 已知限制

- 拖拽过程中连线仍按旧坐标绘制，松手后一次性对齐（避免每帧重算 SVG）。
- 分组框拖动仍走 state（节点多时会重渲染），本轮未改。
