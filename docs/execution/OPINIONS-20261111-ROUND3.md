### N17 技能 vs 提示词库

- 现状是两套数据：
  - `PromptSkill`（`src/types.ts:318`）+ `useSkillStore`（`src/lib/skillStore.ts`）：标题、提示词、标签、变量、封面。
  - `Skill`（`src/types.ts:362`）+ `useCapabilitySkillStore`：名称、基座提示词、参数槽、图片槽、示例、收藏、适用模型。
- 两套 UI：
  - `SkillLibraryView.tsx`（提示词库，232px 侧栏，232 宽）。
  - `CapabilitySkillLibrary.tsx`（技能库，176px 一级 + 160px 分类）。
- 结论：**用户判断成立，功能语义重复**。技能本质上就是“可复用的提示词模板 + 可选参数/图片槽 + 封面/示例”。提示词库没有必要作为独立一级能力存在。

### N21 全局 UI 一致性

初步审计（待参考图确认）：

1. **两套设计系统**：`CapabilitySkillLibrary` 用原生 Tailwind + `slate`；`SkillLibraryView` 用 `ui` 组件 + `text-ink-*`/`bg-surface`/`border-line`。颜色、圆角、字号各一套。
2. **侧栏宽度**：230 / 176+160 / 232，三种。
3. **头部高度**：工作区 44px，技能库搜索栏 48px，弹窗头部不一致。
4. **图标体系**：一级栏是手写 SVG，技能/画布大量 lucide，画布工具栏还有纯文字“左/中/右”。
5. **字号**：技能卡元信息用 `text-[10px]`，其他界面用 `text-caption`/`text-body-sm`。
6. **按钮样式**：黑色胶囊、灰色圆角、幽灵按钮、图标按钮混用，缺少统一层级。
7. **卡片密度**：技能卡三列在 1024 宽下偏挤，封面、标题、描述、元信息、底部操作区高度不统一。
8. **弹窗层级**：技能选择 640px、新增技能 480px、设置/详情宽度和遮罩/圆角/阴影不统一。
9. **命名不统一**：工作区方案 / 技能库 / 提示词库 / 技能流，用户口径与界面口径不一致。
10. **空状态与加载态**：技能库、提示词库各写一套，没有统一组件。

## 3. 判断与建议

### 3.1 技能与提示词库合并（建议做）

建议只保留一个概念：**技能 = 可复用提示词模板**。

```text
技能
├─ 名称 / 分类 / 描述
├─ 基座提示词（可编辑）
├─ 参数槽（可选）
├─ 图片槽（可选，支持单图/多图）
├─ 封面 + 参考图/示例图（多图）
├─ 收藏 / 适用模型 / 来源
└─ 版本 / 时间
```

- “纯提示词”就是没有参数槽、没有图片槽的技能，不再单独建提示词库。
- 旧 `PromptSkill` 迁移到 `Skill`：
  - `title → name`，`prompt → basePrompt`，`variables → slots`，`params` 保留，封面保留。
  - 旧 ID 加前缀，避免与 `builtin:` / `mine:` 冲突。
  - 迁移要幂等，重复启动不能重复导入。
- 删除“提示词库”二级入口；保留旧数据导入/导出兼容。
- 内置技能编辑建议用 **覆盖层**：`builtinOverrides` 增加 `basePrompt`、`slots`、`description`、`name`，并提供“恢复默认”。这样不复制 27 条，也不会丢失内置更新。
- 另一种方案是“编辑时复制为我的技能”，更安全，但会出现内置/副本两份，用户容易混淆；不推荐作为默认。

### 3.2 菜单合并（建议做）

- 一级不变：工作台 / 工作流 / 技能流（名称待确认）。
- 二级只保留一列，宽度统一 **230px**，与工作区一致。
- 二级内容 = “全部 / 收藏 / 我的 / 内置 + 分类”，不再有第三级分类栏。
- 搜索、排序、新增、只看收藏放到右侧内容区头部。
- 工作流页的二级栏也复用同一宽度和同一条左侧基线。

### 3.3 技能多图（建议做，但需确认语义）

建议数据模型：

```ts
coverImageId?: string          // 主图/封面
referenceImageIds?: string[]   // 参考图/示例图，可排序
```

- 详情页：主图 + 参考图网格，支持添加、删除、拖拽排序、设为主图。
- 卡片：显示主图；有参考图时角标显示“N 图”。
- 应用技能时：主图优先填第一个图片槽，参考图填多图槽；超出 `max` 时提示。
- 需要确认：这些图是“示例图（只展示，不参与生成）”还是“必填输入图（应用技能时自动带入）”。两者 UI 和数据结构不同。

### 3.4 工作流旧版（建议按截图还原）

- 左侧二级栏 + 主区域居中卡片，文案与按钮按截图。
- “返回项目”回到工作台；“到 GitHub 提建议”打开当前仓库 Issues。
- 不再显示三张“待开发”能力卡。
- 版本号显示当前版本还是截图里的 `v1.0.0`，需要确认。

## 5. 影响范围与风险

- 数据迁移：`PromptSkill → Skill` 需要幂等迁移、导出/导入兼容、失败回滚。
- 内置覆盖：`builtinOverrides` 扩展后要兼容旧数据，不能让旧覆盖丢失。
- 多图：IndexedDB 图片引用、导出 ZIP、删除撤销都要覆盖。
- 菜单：`SkillsHubView`、`CapabilitySkillLibrary`、`SkillLibraryView`、`AppSidebar` 四处联动。
- 工作流：`WorkflowView` + 二级栏布局，不涉及真实工作流引擎。
- UI 统一：会触碰多个现有组件，必须分批做，不能一次性重写。
