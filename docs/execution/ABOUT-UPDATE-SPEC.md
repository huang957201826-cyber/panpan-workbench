## 1. 为什么改

现在的「关于」页（`AboutSettingsTab.tsx`，69 行）只有：App 卡（名称 / 版本 / 开发者）、第三方许可、开源许可，一条脚注。

问题：
1. **更新入口只藏在左下角的小版本号里**，用户找不到；设置里没有"检查更新"。
2. 没有**更新日志**——用户不知道这版改了什么，也不知道自己落后多少。
3. 没有**反馈入口**——开源项目最重要的一环缺失。
4. 三个分区平铺，没有"版本与更新 / 支持与反馈 / 开源协议"的层级。

## 3. 文案（我定的，三个方向选一）

上游那句是：「本项目的成长离不开每一位用户的使用、反馈、鼓励与支持，愿能一起同行。」

要求"不要一模一样"，我给三个方向，**推荐 A**：

| 方案 | 文案 | 语气 |
|---|---|---|
| **A（推荐）** | **这个工作台还在长，用得顺手的地方请留下，用得不顺手的地方告诉我。** | 务实、有主见、和"工作台"的定位贴 |
| B | 每一张图都从一句描述开始；如果你用它做出了东西，那它就值得继续做下去。 | 偏抒情 |
| C | 一个给自己用的生图工作台。愿意的话，也一起用。 | 最克制 |

配套的次级文案：
- 检查中：`正在检查更新…`
- 最新：`已是最新版本`
- 失败：`检查更新失败，请稍后再试`（若更新通道未启用：`更新通道尚未启用`）
- 下载中：`正在下载新版本… 42%`
- 待重启：`新版本已就绪，重启后生效`

## 4. 更新日志的数据来源

三种方案，推荐 **A + B 兜底**：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A 内置（推荐）** | 构建时把仓库根目录的 `RELEASE.md` 以 `?raw` 打进前端，弹窗用现有 `MarkdownRenderer` 渲染 | 离线可看、无网络依赖、和发布记录天然一致 | 只含当前版本段落（`RELEASE.md` 只保留最新一版） |
| B 远程 | 从 `{repo}/releases` 拉最新 release body | 可看历史版本 | 依赖仓库与网络；没仓库时为空 |
| C 手写 | 前端单独维护 `changelog.ts` | 灵活 | 两处维护，必然不同步 |

**落地口径**：
1. 现在先用 A：`import changelog from '../../RELEASE.md?raw'`，只读、不改文件。
2. `RELEASE.md` 按现有规范只留最新版本 → 弹窗标题写「v1.0.0 更新内容」，若将来要多版本，再引入 `docs/changelog/` 目录按版本存 md。
3. 等 GitHub 仓库上线后，若 B 可用，则在弹窗底部加一行「在 GitHub 查看完整发布记录 ↗」。

弹窗规格：宽 720、最大高 80vh、圆角 16、`e3` 阴影；标题行含版本 + 日期；正文 13/1.6 可滚动；底部「关闭」+「在 GitHub 查看」（可选）。

## 5. 入口策略

| 入口 | 位置 | 作用 |
|---|---|---|
| 设置 → 关于 | 完整信息 + 检查更新 + 更新日志 + 反馈 | 主入口 |
| 左下角版本号（现有 `UpdateEntry`） | 侧栏底部 | 快捷检查；点击后行为不变 |

两处**共用同一份状态**（把 `UpdateEntry` 内的状态机抽成 `useAppUpdate()` hook 或 store 切片），避免"设置里说已是最新、左下角还在转圈"。

## 6. 前置依赖（没有这些，功能会"看起来坏"）

1. **仓库地址**：`tauri.conf.json` 的 endpoint 与关于页的 Issues/LICENSE 链接都指向 `github.com/panpan-workbench/panpan-workbench`，**该仓库还不存在**。
   → 仓库上线前，关于页的「反馈问题 / 使用说明 / 开源许可」应显示为**禁用态 + 提示"仓库上线后可用"**，而不是点了 404。
2. **更新通道**：endpoint 404 时，检查更新要落到「更新通道尚未启用」而不是「检查失败」，避免用户以为是网络问题。
3. **`RELEASE.md` 内容规范**：现有格式（`## v1.0.0（2026-11-07）` + 分类条目）正好可渲染，无需改。

## 7. 验收标准

1. 设置 → 关于 出现 4 个分区，顺序与 §2 一致。
2. 点击「检查更新」能走完：检查中 → 已是最新 / 发现新版本（有徽章）→ 下载进度 → 待重启；每一步文案与 §3 一致。
3. 仓库未上线时，三个外链是禁用态并给出原因，不产生 404。
4. 更新日志弹窗能离线打开，内容与 `RELEASE.md` 当前版本一致，Markdown 渲染正常（标题/列表/代码块）。
5. 左下角版本入口与设置页状态同步（同一时刻两处文案一致）。
6. 深浅主题各截图一遍。
