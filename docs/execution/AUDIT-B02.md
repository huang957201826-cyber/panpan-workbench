## 一、用户本轮四条

### 1. 图片不能拖入无限画布

- 现状：全局 `drop` 只调用 `addImageFromFile`，把图加进输入框参考图；`CanvasBoard` 没有 `onDrop`。
- 证据：`src/studio/StudioShell.tsx:141-154`；`src/components/CanvasBoard.tsx` 无 drop 处理。
- 根因：数据模型只有 `TaskRecord` 节点，没有“纯图片/素材节点”；没有画布落点坐标换算、拖入预览、非法文件提示。
- 同类缺口：画布→输入框、历史流/九宫格→画布、URL 图片、多图拖入、拖入撤销。

### 2. 不能从画布拾取图片作为参考图

- 现状：只有节点“设为参考图”和右侧历史“垫图”；输入框“添加素材”只有本地文件和链接。
- 证据：`BottomPromptBar.tsx` 的 `+` 只触发 file input；`CanvasTaskNode.tsx` 的“设为参考图”是逐节点动作。
- 根因：没有共享“当前拾取目标/画布拾取态”，输入台和画布没有选择总线。
- 同类缺口：从历史多选、同一任务第 2/3/4 张输出、替换已有参考图、选完自动插入 `@图N`、Esc 取消。

### 3. `@图N`、拖入虚化、拖动排序后自动重编号

- 点击缩略图插入 `@图N`：还在（`BottomPromptBar.tsx:161-167`）。
- 输入 `@` 弹出候选菜单/上下键/回车：没了；原版 `InputBar.tsx` 用 contentEditable + `promptImageMentions` + `atImageOptions`。
- 拖入虚化遮罩：没了；原版 `DragUploadOverlay` 只在 `InputBar` 渲染，Studio 输入台未接。
- 拖动排序：拖拽还在；`reorderInputImages` → `updateInputDraftImages` → `remapImageMentionsForOrder` 会重编号，但输入框是纯文本、没有 mention 胶囊，且未做实机回归。
- 根因：换壳时重写了输入台，只搬了简化 textarea，没有迁 contentEditable mention 系统。

### 4. 右下角常驻

- 系统托盘/关窗常驻：未做；`tauri.conf.json` 无 tray，`close_watch.rs` 最终 `destroy` 窗口。
- 画布右下角缩放/画布切换工具：只在画布模式显示，网格模式隐藏，不是常驻。

## 七、画布/输入台/外壳补充审查（真实点击 + 代码）

1. **缩放/适应全部被视图切换盖住（已复现）**：`CanvasBoard` 工具栏 `bottom-4 right-4 z-10`，`StudioShell` 画布/九宫格切换 `bottom-3 right-3 z-30`。点“适应全部”实际切到了九宫格；`+`/`−` 部分区域也被盖住。用户说的“没反应/没有全览按钮”就是这个。

9. **提示词无长度上限**：底部/右侧 textarea 都没有 `maxLength`，长提示词进 task/workspace 无提示。

## 九、屏幕分辨率 / DPI / 字体尺度审查

### 当前事实

- 默认窗口 `1280×820`，最小 `800×600`，居中；之后由 `tauri-plugin-window-state` 恢复位置/大小（`tauri.conf.json:12-24`、`lib.rs:42-48`）。
- 没有“界面缩放/密度”设置；全部是固定 px。
- 统计到 `147` 处 `text-[9px]`–`text-[12px]` 或 24px 小按钮；大量正文/标签实际只有 10–11px。
- `index.html` 的 viewport 设置了 `maximum-scale=1, user-scalable=no`，Web/PWA 不能缩放。
- Studio 的字体栈写的是 `Geist` / `Space Grotesk` / `JetBrains Mono`，但仓库没有对应字体资产；实际会回退到系统字体，不同 Windows 上观感不一致。全局 `--font-ui-sans` 是 HarmonyOS Sans SC，但 Studio 用的是另一套 `--studio-font-sans`。
- 断点只有 `900`（侧栏收起）和 `1100`（右侧抽屉浮层），没有 2K/4K 的“大屏放大/限宽”策略。

### 风险矩阵

| 环境 | 会发生什么 |
|---|---|
| 1920×1080 @100% | 1280×820 窗口占大半屏，10–11px 正文偏小，长时间看吃力 |
| 1920×1080 @125% | 10px 逻辑字变 12.5px 物理，基本可读；窗口 1600px 物理，仍偏大 |
| 2560×1440 @100% | 10px 物理字很小；窗口只占半屏，画布/抽屉显得空 |
| 2560×1440 @150% | 10px→15px 物理，可读；但 1280 逻辑宽只占一半，布局没放大 |
| 3840×2160 @100% | 10px 物理字几乎不可读；1280 窗口只占 1/3，这是“严重变小”的场景 |
| 3840×2160 @200% | 10px→20px 物理，可读；但窗口 1280 逻辑在 1920 逻辑屏上仍偏小 |
| 多显示器混合 DPI | 窗口跨屏/换屏时 WebView2 会重算 DPR，画布占位层有 DPR 处理；但窗口 bounds 只在启动恢复，没有看到越界校验 |
| 800×600 最小窗口 | 侧栏 230 + 抽屉 360 后画布只剩约 210px，三栏布局不可用 |

### 结论

- 不是“4K 一定字变小”，而是 **4K @100% 且没有 UI 缩放** 时必然过小；1080P @100% 也已经低于成熟桌面软件的正文基准。
- 成熟软件通常：正文 13–14px、次要 12px、标签 11px 下限；跟随系统 DPI；另提供 100/110/125/150% 界面缩放；默认窗口按工作区比例打开。
- 当前是“AI Studio demo 的紧凑视觉”，不是“长时间使用的桌面工具尺度”。

### 需要补的方案

1. 定义字号阶梯：正文 13px、次要 12px、标签 11px 下限、标题 15–16px；先用 rem，再给根字号缩放。
2. 设置 → 外观增加“界面缩放：跟随系统 / 100 / 110 / 125 / 150%”，只缩放 UI chrome，不缩放画布世界坐标。
3. 默认窗口改为工作区的 80%（上限 1440×920，下限 960×640）；恢复窗口状态时校验是否落在当前显示器内，越界则居中。
4. 增加大屏断点：≥1600px 时放大侧栏/抽屉/输入台上限，避免 2K/4K 下所有内容挤在左侧。
5. 最小窗口从 800 提高到 960，或在 <960 时强制抽屉浮层/隐藏侧栏。
6. 字体统一：要么打包 Geist/Space Grotesk/JetBrains Mono，要么 Studio 复用 `--font-ui-sans`，不要写不存在的字体名。
7. Web/PWA 去掉 `user-scalable=no`，允许浏览器缩放。
8. 验证矩阵：1920×1080@100/125、2560×1440@100/150、3840×2160@150/200、800×600、混合 DPI 双屏。

| 间距节奏 | 4/6/8/10px 混用 | 4/8 网格为主 | 不统一 |
| 字号阶梯 | 8/8.5/9/9.5/10/10.5/11/11.5/12/12.5/13/14/15/17 | 11/12/13/14/16/18 | 层级差 0.5px，实际不可辨 |

结论：不是“4K 才小”，而是 **1080P 下已经小一档**；4K@100% 只是把小问题放大成不可读。留白也偏紧：10px 文字配 2–4px 垂直内边距，视觉上会显得“挤在一起”。

### “微放大”建议（不重做布局）

按你的 9→12 级别，但分两档，避免一次撑爆：

- 字号：
  - `9 / 9.5` → `11.5 / 12`
  - `10 / 10.5` → `12`
  - `11` → `12.5`
  - `11.5` → `13`
  - `12` → `13.5`
  - 正文统一到 `13`，标题 `15–16`
  - `8 / 8.5` 只保留给角标，且不小于 `10`
- 图标：
  - `12 → 14`，`14 → 16`，`16 → 18`，主工具栏 `20 → 22`
  - 图标按钮点击区 `24 → 30–32`；触屏目标 `44`
- 留白：
  - 卡片 padding `10 → 12`，密集行 `6 → 8`，组间 `8 → 10/12`
  - 胶囊高度 `26 → 30`，行高按 1.5–1.6 倍字号
  - 保留 4px 网格，但不要所有地方都用 4px
- 不要：
  - 不要全量 +4px；不要改布局结构；不要把所有按钮都做成 44px 桌面尺寸；不要把画布世界坐标一起缩放。

### 其他 UI 规范问题

- 字号阶梯不是阶梯：0.5px 的差异人眼几乎看不出来，层级实际靠颜色和字重。
- 大量 `text-slate-400` + 9–10px 小字，浅色背景上对比度不足；需要按 WCAG AA 小字 4.5:1 复核。
- 很多图标按钮只有 hover，没有 `focus-visible`；键盘用户看不到焦点。
- 滚动条 4px 偏细；高分屏 0.5px 边框可能发虚。
- 禁用态 `opacity-35` 在浅色/深色下都可能过低。
- 中文 10px 比英文更吃力；CJK 正文建议不低于 12px。
- 触屏目标 24px 远低于 44px；目前主要靠鼠标，但托盘/平板场景会难用。

## 十一、结论

用户本轮四条都不是“单点 bug”，而是 B01 只做了最短路径：拖拽只接到输入框、参考图只做了节点动作、@ 只留了文本插入、图标只换了 OS 资产。基础层还有安装路径/命名/快捷方式/图标资产不统一的问题。以上已记录，等确认后一起改。
