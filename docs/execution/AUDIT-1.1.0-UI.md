# AUDIT — 1.1.0 UI 按钮与基础功能审计（2026-11-12）

- 状态：只审计、只记录；本文件完成后仍不改代码。
- 范围：当前 1.1.0 安装版 + 源码 + Playwright/mock。
- 结论：**不是“所有按钮都假”，但确实存在基础功能缺口和死入口**；本轮先列清单，后续按批次修。

## 1. 用户实测问题复现

### 1.1 单任务节点拖动后撤销无效（已复现）

- 操作：生成一个任务 → 拖动任务节点 120px → 点左上角撤销。
- 结果：节点从 `x=448.5` 移到 `x=568.5`；撤销按钮 `disabled=true`；点击后仍在 `x=568.5`。
- 证据：`docs/execution/evidence/audit-undo-task.png`。
- 代码原因：`pushPositionUndo` 只在组拖（`commitGroupDrag`）和对齐（`alignSelection`）里调用；单节点拖动、单素材拖动/缩放没有入栈。
- 结论：撤销目前只覆盖“组拖 + 对齐/排列”，不覆盖用户最常用的单节点移动。**P0**。

### 1.2 单素材拖动/缩放没有撤销

- 代码路径：`CanvasBoard.tsx:970-1028` 的 `imageDrag` 只更新预览并 `updateCanvas`，没有 `pushPositionUndo`。
- 结论：素材节点的移动、缩放都不进撤销栈。**P0**。

### 1.3 保存图片扩展名问题（用户实测 + 代码定位）

- 用户现象：保存图片时文件名没有自带格式，需要手动输入 `.jpg`/`.png`。
- 代码可疑点：
  - `src/lib/exportFileName.ts:27` 的 `sanitizeFileNamePart` 直接 `slice(0, 120)`，长文件名可能把末尾 `.png` 一起截掉。
  - `src/lib/downloadImages.ts:186` 的扩展名来自 Blob MIME；非标准 MIME 可能得到 `octet-stream` 之类。
  - `src-tauri/src/files.rs:247-286` 的保存对话框用传入文件名推断 `lpstrDefExt`；如果文件名已被截断/没有扩展名，就没有默认扩展名；保存后也没有强制补扩展名。
  - `downloadTaskOutputs` 使用 `task-${id}` 作为 base，理论上应带扩展名；说明问题更可能出在长文件名截断、MIME 或对话框过滤器。
- 结论：保存链路没有“设置格式 → 默认文件名 → 对话框过滤器 → 保存后补扩展名”的单一契约。**P0**。

## 4. 额外发现的产品问题

1. **抽屉折叠入口缺失**：1.1.0 删掉了 TitleBar 的“应用/编辑”和侧栏切换按钮，但二级抽屉没有补折叠按钮；`sidebarCollapsed` 只会在窗口初始宽度 <900 时自动为 true，用户无法主动收起，“展开方案”胶囊平时不可达。**P0/P1**。
2. **两套导航表达同一件事**：左侧方案列表和画布顶部方案胶囊都在切画布，容易产生状态/文案不一致；应明确“列表看全量，胶囊切当前/最近”。
3. **删除功能没有落位**：搜索、筛选、多选、九宫格如果直接从画布顶部删掉，必须有替代入口，否则不是减法而是功能丢失。
4. **“更多”变成杂物抽屉**：生成参数、应用设置、导航动作混在一起；用户找不到，也不符合“设置类进设置”的原则。
5. **保存/导出契约不统一**：格式设置、实际 Blob MIME、文件名扩展名、保存对话框过滤器、保存后补扩展名是五段逻辑，没有单一事实来源。
6. **撤销不是命令栈**：目前是“位置快照栈”，只覆盖组拖/对齐；用户期望所有移动、缩放、删除、排列都能撤销。
7. **旧代码/死按钮**：`CanvasWorkbench` 旧界面的三个无处理器按钮已删除（R7），保留“图像生成”；旧界面仍不重构，后续可整体退役。
8. **缺少按钮契约测试**：已补 `docs/execution/BUTTON-CONTRACT.md`（R7），记录扫描口径、关键按钮期望结果与 E2E/单测/人工验收方式。
9. **UI 细节未统一**：更多菜单的字距、选项间距、选中态、圆角、按钮高度与主界面不一致；参考截图是 28px 高胶囊、统一 8px 间距。
10. **技能卡“图标”语义弱**：27 条技能用同一 Sparkles + 色块，缺少类别/技能识别度；封面可换，但默认封面没有区分。

## 5. 建议的修复顺序（只记录，未执行）

1. 先修 P0 基础功能：保存扩展名、单节点/素材撤销、抽屉折叠入口。
2. 再做画布减法：项目列表去折叠、右上工具条删除、九宫格移到输入框、搜索/筛选/多选落位。
3. 再拆“更多”：质量独立、格式加 GIF/SVG、遮罩/右侧停靠图标化、删复制配置/图片链接。
4. 最后做 UI 细节统一与按钮契约测试。

## 6. 本轮结论

- 主链路真实可用，不是大面积假按钮。
- 但“撤销”和“保存格式”是基础功能缺口，必须先修。
- 参考截图的画布顶栏减法、项目列表减法、更多菜单减法是下一轮 UI 的主线。
- 本文件只记录；未改任何代码。
