# PLAN-WORKFLOW-20261113 · 工作流板块填充方案

- 阶段编号：W1–W5
- 前置：`1.2.1-RELEASE` 已收口，发布锁 `locked`
- 性质：**只填内容，不新增一级 UI**
- 关联资产：`docs/workflows/`（6 条 MIT 工作流）

---

## 一、目的

把侧栏里那个空着的「工作流」入口，填成**本地工作流库**：
用户在这里选一条成熟工作流、调几个参数、点运行，结果直接进现有画布和任务历史。

一句话：**让 ComfyUI 变成软件内部的一个「引擎选项」，而不是另一个要打开的软件。**

---

## 二、最终形态（做完是什么样）

1. 左侧栏点「工作流」，看到 6 张工作流卡片（打底 / 控图 / 多角度 / 重绘），每张标明需要哪些模型。
2. 选一张，右侧出现它的参数面板（提示词、参考图、结构强度、重绘幅度），全部是现有样式的滑杆和 pill。
3. 点「运行」，任务进入现有任务条，出图直接落到当前画布，跟云端生图的图混在一起。
4. 画布上多选 10 张 SU 截图，右键「用工作流批量生成」，排队出 10 张。

**没有新增导航、没有新增弹窗体系、没有第二个画布。**

### W1 · 本地引擎连接（0.5 天）

**做什么**

### W4 · 参数面板（1–2 天）

**做什么**
- 每条工作流带一份 `params` 声明（字段名、类型、范围、默认值）。
- 右栏按声明渲染：滑杆（结构强度 0–1、重绘幅度 0–1）、数字（种子、步数）、开关（4 步加速）。

**验收**：结构强度 0.3 与 0.9 出图明显不同；参数能记住，下次打开还在。

**回滚**：参数面板隐藏，只用默认值。

## 六、数据模型

```ts
interface WorkflowManifest {
  id: string
  name: string
  category: 'base' | 'control' | 'angle' | 'inpaint' | 'upscale'
  description: string
  file: string                       // 相对路径，指向 JSON
  anchors: Record<string, string>    // __PROMPT__ -> 节点 title
  params: Array<{
    key: string
    label: string
    type: 'text' | 'image' | 'number' | 'range' | 'boolean'
    default: unknown
    min?: number
    max?: number
    step?: number
  }>
  requires: { models: string[]; nodes: string[] }
  estimateSeconds: number
  license: string
}
```

## 七、锚点规范（关键工程决策）

工作流 JSON 里节点 id 是随机 uuid，换个版本就变。所以**不按 id 绑定，按标题绑定**。

改造步骤（一次性，手工）：

1. 在 ComfyUI 里打开工作流；
2. 把「正向提示词」节点改名为 `__PROMPT__`，「载入图像」改名为 `__IMAGE__`，「种子」改名为 `__SEED__`；
3. 重新导出 JSON，放进 `src/studio/workflows/`；
4. 驱动器遍历 `nodes`，按 `title` 匹配，写 `widgets_values`。

好处：别人给的任何工作流，只要标了这四个锚点就能直接接进来，**永久免适配**。

## 八、风险与对策

| 风险 | 对策 |
|---|---|
| ComfyUI 版本漂移导致节点失效 | 锁版本；JSON 与版本号一起存进仓库 |
| 模型缺失导致跑一半报错 | W2 的预检前置拦截 |
| 12 GB 显存不够 | 主模型用 `int8_convrot`；控制流用 Lightning 4 步 |
| 许可 | 6 条 JSON 为 MIT，可分发；ComfyUI 一律外挂，不打包 |
| 用户不会装 ComfyUI | 文档给一键整合包；软件内只做「检测到未安装」提示，不做安装器 |
