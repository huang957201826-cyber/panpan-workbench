# 前端 UI 全量体检（2026-11-07）

- 范围：整个 Studio 外壳（侧栏 / 项目面板 / 画布 / 九宫格 / 底部输入台 / 技能库 / 设置弹窗）+ 交互状态（hover、选中、焦点、菜单、滚动）
- 方式：源码逐处定位 + 实机窗口抓图（`PrintWindow`）+ 用户提供截图 + 参考项目逐行比对
- 状态：**只记录，未改任何代码**
- 结论：骨架（AI Studio 风格）已经移植到位，问题集中在三件事 —— **没有设计系统**、**头部/底部两个枢纽区的信息架构混乱**、**控件太多却没有层级**。不是"哪里丑"的散点问题，而是缺少一层规范。

## 0. 一句话总评

> 现在是一个"每一块单独看还行、拼在一起不像一个产品"的状态。
> 视觉语言有 3 套在打架（Studio 玻璃拟态 / 设置页旧上游样式 / 原生 select 与 tooltip），
> 字号有 16 种，圆角 6 种，图标 3 种画法，主操作区还压着 12 个同等权重的控件。
> 这些属于"系统缺失"，逐点打补丁会越补越乱，建议按"先定规范 → 再改布局 → 最后磨细节"的顺序做一次。

## 2. 你提的 6 条：现象 → 根因 → 建议

### UI-01 技能库要严格参考 Google AI Studio 那个源码

**现在的样子**（`src/studio/components/SkillLibraryView.tsx`，140 行）：
一行 flex-wrap 把「技能库」标题 + 搜索 + 分类 select + 标签 select + 排序 select + 新建按钮挤在一起；下面是纯文字卡片（标题 / 提示词 3 行 / 分类与标签 / 参数行 / 使用・编辑・删除）。

**参考源码**（`aether-.../src/components/SkillHubView.tsx`，495 行）：

| 区域 | 参考做法 | 我们 |
|---|---|---|
| 顶栏 | 42px 高，左侧**分类分段 tab**（全部/商业空间/光影夜景…）每个带 `(数量)`；右侧搜索框（聚焦时 48→56px 展开）+ 模型下拉 | 一行 5 个控件平铺，分类是原生 select，无计数 |
| 卡片 | 16:9 预览图 + 左上分类徽章 + 右上收藏星 + 图底模型名/参数槽数 + 标题 + 描述 + `#标签` + 底栏「复制配方」「一键调用」 | 无预览图、无收藏星（只有置顶星）、无复制、按钮是「使用/编辑/删除」 |
| 空状态 | 图标 + 「未匹配到相关技能配方」 | 有，但样式不统一 |
| 详情 | 点卡片开 **Inspector 双栏弹窗**：左=预览+设计说明+推荐底模/作者；右=可调参数槽 + 实时合成提示词 + 复制全文；底部=关闭 / 注入到当前工作区 | 只有 123 行的扁平编辑表单 |

**建议**（分两步，别一次做太大）：
1. **第一步只改 UI 结构**（不动数据模型）：42px 顶栏（分类 tab 用现有 `category` 聚合、带计数）+ 卡片加 16:9 预览区（无图时用按 `id` 生成的确定性渐变/点阵占位）+ 收藏与置顶合并成一个星标 + 底栏改为「复制提示词 / 使用」+ 点卡片开详情弹窗（左信息右提示词，可直接使用）。
2. **第二步加能力**：`previewUrl`（从任务保存技能时抓输出缩略图）、变量槽 `{{subject}}` 与实时合成、使用次数排序。

### UI-02 蓝色光标

**现状**：两套独立特效叠在一起。
- `.canvas-blue-glow`（`src/studio/studio.css:156-181`）：150px 径向光晕（alpha 0.16）+ 22px 内圈（0.28）+ 中心 5px 蓝点 + 12px 外发光，`is-active` 才显示，只监听 pointerleave 淡出。
- `InteractiveDotGrid`（`src/components/InteractiveDotGrid.tsx`）：光标 135px 内的点实心化（alpha 0.15→0.65）+ 半径 0.95→1.4 + 弹性推开 3.5px + 微粒。

**为什么难受**（专业判断）：
1. **语义重复**：点阵已经用「变实心」表达了"我在这里"，再叠一层蓝光就是两个中心、两种语法。
2. **尺度不匹配**：150px 的光斑跨了 6 个点阵格（24px 间距），看起来像一块糊在纸上的蓝色污渍，而不是"光"。
3. **颜色割裂**：点阵实心化用的是墨黑 `rgba(15,23,42)`，蓝光是纯蓝，两者没有共同的色彩逻辑。
4. **静止不消失**：只在 pointerleave 才淡出，鼠标停在画布上不动时，那块蓝光一直挂着。

**三个方案（推荐 A）**：
- **A. 让点阵自己发光**：删掉 `.canvas-blue-glow` 整层；把点阵的实心色从墨黑改成品牌蓝 `rgba(59,130,246,·)`，alpha 随距离衰减；光晕直径收到 72–90px 并去掉中心蓝点。效果是"点被点亮"，而不是"盖了一个光斑"。
- **B. 保留一层极淡光晕**：直径 ≤90px、alpha ≤0.08，删掉 5px 中心点与外发光，只做背景提亮。
- **C. 彻底去掉**：只留静态点阵 + 点阵实心化（性能最好，最克制）。

配套（三方案都要）：静止 800ms 后整体淡出；拖拽/框选时不跟随；`prefers-reduced-motion` 保持关闭（现在已有兜底）。

### UI-03 左侧栏偏窄、图标比例不舒服

**现状**（`AppSidebar.tsx:105-175`）：rail 44px，按钮 32px，图标 15px，`gap-2`(8px)，logo 28px。
参考项目也是 44px / 32px，但它的图标是 16–18px 且上下留白更紧 —— 所以问题不只是宽度，是**图标占按钮的比例**：15/32 = 47%，视觉上"空心的方块里塞了个小图标"。

**建议**：
- rail **44 → 56px**，按钮 **32 → 40px**，图标 **15 → 18px**（比例 45%→稳定），logo 28 → 32px，间距规整为 6px/12px 两档。
- 激活态：目前是灰底块，建议改为「左侧 2px 蓝条 + 10% 蓝底」，一眼能看出"当前在哪"。
- 底部分组（设置/版本）加一条 1px 分隔线，与主功能区拉开。
- 悬停态统一：圆角 8px、背景 `rgba(0,0,0,.04)`、120ms。

### UI-04 顶部应该是独立一行（左标题 + 右控件）

**现状是两套结构**：
- 画布：`StudioShell.tsx:716-741` 把工具栏做成**浮在画布上的白色圆角卡**（`absolute left-3 right-3 top-3`，`max-w-[720px]`，`flex-wrap`），所以会遮挡画布内容，窗口一窄就折行变成两块。
- 九宫格：`CardGridView.tsx:94-108` 是内容区里的「九宫格历史卡片」标题行 —— 这才是你说的"独立一行"，但它**跑在滚动容器里**（`overflow-y-auto`），往下滚就没了。

**建议**：抽一个 `StudioHeader`，两种模式共用、不浮动：
```
┌─────────────────────────────────────────────────────────────┐
│ 项目 · 画布名   12 张    ● 生成中 2        [搜索][状态][模型][★][多选][画布|九宫格] │
├─────────────────────────────────────────────────────────────┤ 48px，border-bottom
│ 已选 3  全选  清除            收藏  下载  删除                │ ← 多选时才出现的第二行
└─────────────────────────────────────────────────────────────┘
```
- 高度 48px，`sticky`，与左侧面板 44px 头部对齐（或统一都 44px）。
- 左侧永远是"我在哪"（项目/画布名 + 数量 + 运行状态），右侧永远是"我能做什么"。
- 好处：不遮画布、切换视图不位移、滚动不消失、和左面板形成一条横线。

### UI-05 悬停图片节点弹出的半透明卡片

**现状**：
1. `CanvasTaskNode.tsx:420` 底部浮层：`bg-[#0b1220]/78` + 蓝色描边 + 蓝色外发光，`translate-y-2 → 0`，hover 出现，显示提示词两行。
2. 节点容器上还有 `title={title}`（:260、:296）→ 浏览器**原生白色 tooltip**（你截图里那个白框"生成一个橘子"）。

**为什么丑**：hover 是个"轻"状态，却弹出一个占满整宽的深色块；它同时和选中工具条、尺寸标签、"成品"徽章、下载按钮抢同一块空间；原生 tooltip 不可控、跟随系统主题、和深色玻璃完全不是一套。

**建议**：
- 直接删掉底部浮层（UI-05-a）。
- 删掉 `title` 原生 tooltip，改用统一 Tooltip 组件（延迟 400ms、12px、深色玻璃、圆角 6px、最多两行）——只在图标按钮上用。
- 提示词要看，就在**选中**时于节点下方显示一行 12px 单行省略（或放进右侧详情），不要靠 hover。

### UI-06 选中文字等基础交互样式

**现状**：`::selection` 只在旧输入框的 contenteditable 里定义过（`src/index.css:477-508`）。Studio 输入台用的是**透明 textarea + overlay 文字**（`BottomPromptBar.tsx:449-465` + `PromptMentionOverlay`），所以选中时：浏览器给 textarea 画蓝色选区块，overlay 的文字浮在上面 → **重影**（你截图 2 就是这个）。全项目也**没有一条 `:focus-visible`**。

**建议（这是"有没有系统"的分水岭）**：
1. 全局 `::selection { background: rgba(59,130,246,.22); color: inherit; }`。
2. 输入台二选一：
   - 稳：overlay 层同步 `selectionStart/End`，选中时隐藏 overlay 的对应文字，只用浏览器选区；
   - 好：换成 contenteditable + 不可编辑的 mention chip（旧版 InputBar 已有这套，可移植）。
3. `:focus-visible` 统一 2px 蓝环（`outline: 2px solid rgba(59,130,246,.6); outline-offset: 2px`），键盘可达。
4. 滚动条统一：现在 `no-scrollbar` 到处用（`studio.css:37`），列表能不能滚用户看不出来 —— 至少 hover 时显示细滚动条。
5. 禁用态统一：现在是 `opacity-35`/`opacity-40`/`opacity-30` 三种。

### UI-07 底部输入台控件展不开 / 被裁

**现状**（`BottomPromptBar.tsx`）：
1. 参数行 `overflow-x-auto no-scrollbar`（:479）——宽度不够就把后面裁掉。你截图里 "更多 · PNG · 透明 false · 审核 auto" 被裁成 **"更:"**，后面的图标组也被压。
2. `FloatingMenu`（`FloatingMenu.tsx`）固定 `top: rect.top - 6` + `translateY(-100%)`，**没有 max-height、没有内部滚动、不会向下翻转** —— 窗口矮或菜单长（"更多"菜单 256px 宽、内容很长）时向上溢出，被窗口边裁掉。
3. 尺寸菜单里 `res` 和 `label` 同时打印（:532-539）：`2560×1440  16:9 · 2560×1440`，信息重复。

**建议**：
- 参数区改**两行**结构：`[提示词 + 发送]` / `[模型 · 尺寸 · 质量 · 数量 · 更多 …… 图标组]`，允许换行、不横向裁切；低优先项（格式/透明/审核）收进"更多"。
- `FloatingMenu` 加：`max-height: min(70vh, 320px)`、内部滚动、`flip`（上方空间不足自动向下）、与锚点 8px 间距、进入 120ms 淡入+位移 2px。
- 尺寸项只显示 `1K 16:9 · 1280×720` 一行；当前选中项用 ✓ 而不是灰底。
- 控件分级：**主操作**（发送）实心黑；**次操作**（模型/尺寸/质量/数量）pill；**工具**（加图/遮罩/链接/拾取/存技能/停靠）**收进一个"＋"或"工具"二级菜单**，不要 6 个圆钮平铺 —— 这就是现在密不透风的根因。

## 3. 我额外查到的问题

### UI-08 / 设计令牌缺失（根因级）
- 字号：全项目 **16 种任意值**（8 / 8.5 / 9 / 9.5 / 10 / 10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 13.5 / 14 / 15 / 16 / 17px），其中 9px 及以下用了 **33 处**；`text-[10px]` 68 处、`text-[11px]` 59 处。
- 圆角：`rounded / md / lg / xl / 2xl / 3xl / [_px]` 混用；阴影从 `shadow-xs` 到 `shadow-2xl` 无层级。
- CSS 里只有颜色变量（`index.css:6-15` 的 HSL），**没有 spacing / radius / type / elevation / motion 令牌**。
- 建议：定 5 档字号（11 辅助 / 12 正文 / 13 强调 / 15 标题 / 18 大标题）、4 档间距（4/8/12/16）、3 档圆角（6/10/14）、3 档阴影（卡片/浮层/模态）、2 档动效（120ms 微交互 / 200ms 展开），然后**只允许用这四套值**。

### UI-09 原生 select 混在自绘组件里
右上工具栏的"全部""全部模型"、技能库的三个下拉，都是浏览器原生 `<select>`：箭头样式、下拉面板、高亮色全部跟随系统，和旁边的自绘 pill（圆角、hover、选中态）不是一个世界。建议换成统一的 `Menu` 组件（`FloatingMenu` 已经有基础），或至少在 select 外面包一层统一样式壳。

### UI-10 图标三套画法
- 手写 SVG：`AppSidebar`、`CanvasTaskNode`、`BottomPromptBar` 的停靠图标。
- lucide：`BottomPromptBar` 的 Plus/Layers/Link/Crosshair/BookmarkPlus 等。
- 文字按钮：工具栏的"多选""全览"、节点工具条的"复用参数/保存为技能…"。
三种线宽（1.3 / 1.4 / 1.8 / 2.2）混在一起。建议全量收敛到 lucide（或统一一套自绘），线宽固定 1.6，尺寸固定 16/18/20。

### UI-11 平台细节
生成按钮上是 `⌘↵`（`BottomPromptBar.tsx:791`），placeholder 里写的是 `Ctrl+Enter` —— 一个应用两种说法，且 `⌘` 在 Windows 上不成立。建议按平台取文案（`navigator.platform` 或 Tauri `os`），Windows 显示 `Ctrl+↵`。

### UI-12 枚举值外露
"更多 · PNG · 透明 **false** · 审核 **auto**"（:610 附近）—— `false` 是代码里的布尔值，直接呈现在 UI 上。建议格式化为"透明 关 / 开"，`auto` → "自动"。

### UI-13 / UI-14 节点选中态
`CanvasTaskNode.tsx:424-440` 的四个手柄是 `h-3.5 w-3.5` + `border-white bg-black`（浅色主题下是黑方块），加上容器 1.5px 黑框 —— 在浅灰画布上非常抢眼，像老式图片编辑器。建议：1px `#3B82F6` 边框、手柄改 8px 白底蓝边圆点、悬停放大 1.2 倍、只在 hover 手柄时显示。
尺寸标签（`auto`）在 `bottom-0 left-0`，正好被左下角手柄压住（截图里能看到 "auto" 被裁）。建议移到右上信息区或工具条里。

### UI-15 letterbox 背景
图片 `object-contain` 后左右留白是纯白，和画布背景 `#fbfcfd` 只差一点，节点边界消失（截图里橙子两侧的白条与画布糊在一起）。建议节点内底色用 `#f1f3f7`（sunken），加 1px 内描边。

### UI-16 / UI-17 九宫格头部
标题行在滚动容器内（`CardGridView.tsx:88-108`），滚一下就没了；右侧那行"悬停卡片可设为垫图/参考图 · 点击卡片全屏检视"是**说明文字**，却占着操作位。建议标题行 sticky（或并入 UI-04 的统一 header），说明文字挪到空状态或首次提示里。

### UI-18 空状态
画布空状态只有一行字（`CanvasBoard.tsx:811`：「还没有内容，拖入图片或在左侧输入提示词开始生成」），没有插画、没有"从示例开始/打开技能库"的入口。技能库空状态有图标和两个按钮，两者风格也不一致。

### UI-19 设置弹窗与 Studio 断层
设置页（web 截图 `06-settings.png`）还是旧上游的灰白卡片风：方角、细灰边、原生开关；Studio 是圆角玻璃 + 蓝调。同一个应用两套视觉语言，用户会觉得"点进设置像换了个软件"。

### UI-20 底部控件密度（这是"难受"的最大来源）
一行里：5 个 pill（模型/尺寸/质量/数量/更多）+ 6 个 24px 圆形图标（加图/遮罩/链接/画布拾取/存技能/停靠）+ 1 个发送 = **12 个控件**，其中 6 个是同等权重的圆形图标，点击区只有 24px（低于 32px 可用下限）。建议按上文分级：主操作 1 个、参数 3–4 个、其余进"工具"菜单。

### UI-21 头部高度不齐
标题栏 `h-[38px]`（`TitleBar.tsx:71`），左面板头部 `h-[44px]`（`AppSidebar.tsx:202`），画布无头部 —— 三条横线不在一条基线上。

### UI-22 画布被工具浮层遮挡 + 顶部空白带
工具浮层压在画布上（`top-3`，高约 44px），节点从下面开始排布；同时画布顶部因为没有 header 而留出约 48px 空白，视觉重心下坠。统一 header 后这两个问题一起消失。

### UI-23 无障碍底线
- `:focus-visible` 全项目只有 2 处（都在设置页 About），Studio 主界面一处都没有 → 键盘 Tab 时看不出焦点在哪。
- 9px/9.5px 字号 33 处，浅色下 `text-slate-400`（约 3.4:1）未达 AA 4.5:1。
- 图标按钮多数只有 `title`，没有 `aria-label`（`AppSidebar` 有，`BottomPromptBar` 部分没有）。
