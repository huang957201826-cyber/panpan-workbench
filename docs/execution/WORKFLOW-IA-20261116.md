# 工作流板块的信息架构（IA）

- 日期：2026-11-16
- 状态：**待确认，未改代码**
- 背景：用户明确「工作流是以项目文件夹为导向的」

---

## 1. 核心判断

**工作流属于项目，不属于软件。**

现在的实现是反的：左侧列 6 条预设，参数按预设 id 存进 localStorage。
等于把「软件自带的模板」当成了「用户的数据」，所以：

- 换项目不换上下文；
- 参数被预设共享；
- 跑出来的东西没有归属，切走就没了。

---

## 2. 目标结构

```
工作流
├─ 我的工作流（按项目分组，与「工作区」侧栏同一套项目）
│   ├─ 项目 A                    ⌄
│   │   ├─ 客厅效果图 · v2         上次运行 11-16 10:20
│   │   ├─ 立面方案 · 材质对比      上次运行 11-15 22:10
│   │   └─ + 新建工作流
│   ├─ 项目 B                    ⌄
│   └─ 收藏 / 最近
└─ 技能（6 条预设，只读）
    ├─ 打底 · 参考图编辑
    ├─ 结构控制 · 精准控图
    └─ ...
```

### 规则

| # | 规则 |
|---|---|
| 1 | **预设只读**。点「使用」= 在当前项目下**新建一条工作流**（复制参数），此后编辑的是副本，预设永远不被改 |
| 2 | **工作流属于项目**。切换项目 = 切换整套工作流列表与上下文 |
| 3 | **一切都保存**：参数、参考图、结果、视口、运行时间 |
| 4 | **每次运行落成任务记录**，结果同时进该项目画布，历史可回溯 |
| 5 | 预设不进入「我的工作流」，两块物理分开 |
| 6 | 删除项目时，其工作流一并提示处理；备份 ZIP 要包含项目工作流 |

## 3. 数据模型（草案）

```ts
interface ProjectWorkflow {
  id: string
  projectId: string
  name: string              // 默认「预设名 · 序号」，可改
  presetId: string          // 来源预置，用于显示与升级对比
  canvasId?: string         // 结果落到哪个画布
  params: {
    prompt: string
    negative: string
    strength: number
    model: string
    width: number
    height: number
    count: number
    seed?: number
  }
  referenceImageIds: string[]
  results: Array<{ imageId: string; taskId?: string; createdAt: number }>
  viewport?: ViewportTransform
  lastRunAt?: number
  createdAt: number
  updatedAt: number
}
```

与现有结构的关系：复用 `Project` / `ProjectCanvas` / `TaskRecord`，新增 `ProjectWorkflow`，挂在 `projectId` 下。

## 4. 界面（照搬工作区侧栏的交互）

- 顶部：搜索 + 新建
- 项目行：可展开/收起（chevron）、名称、右侧计数
- 展开内容：该项目的工作流条目，显示名称 + 上次运行时间
- 底部独立区块：「技能」，折叠，列出 6 条预设
- 点预设：若当前无项目，提示先建项目；有项目则新建一条工作流并选中

---

## 5. 与现状的冲突（必须改）

| 现状 | 冲突 |
|---|---|
| 左栏列 6 条预设 | 预设占了「我的数据」的位置 |
| 参数存 `panpan-workflow-values`（按预设 id） | 跨项目共享，正是「预设被污染」 |
| 运行结果只在节点里 | 没有落库、没有历史 |
| 工作流页不读项目 | 切项目无变化 |
