## 1. 本阶段交付

### 1.1 九宫格工具栏

- 复用 `CardGridView` 现有 header 行，不新增第二行。
- 搜索：提示词/模型文本。
- 状态筛选：全部/完成/失败/生成中。
- 收藏筛选。
- 多选模式：卡片左上角 checkbox，点击卡片切换选中。
- 批量操作：全选、收藏、下载、删除（确认后 `removeMultipleTasks`）。
- 切换画布自动清空选择。
- 卡片保持 3 列、16:9、hover 工具条、详情/垫图/复用/下载。
- `CardGridView` 接入 `useVirtualGrid` 的容器滚动模式，只挂载可视区卡片。
- 右侧历史流只渲染最近 30 条，滚动到底部用「加载更多」追加，避免 1000/3000 条记录全量挂载。
- 九宫格/历史流图片改为 `ArtboardThumb` 按需加载，只读取当前挂载卡片的输出图，不再一次性加载全部任务图片。
- 生成中的提示改为 header 内的小状态点，不再额外渲染一张未计入虚拟列表的 shimmer 卡片。
- 右侧历史流 `visibleCount` 在切换画布时重置为 30。

### 1.2 画布真实比例

- 新增 `canvasNodes.ts`：
  - 初始宽 360；`h = clamp(360 * imageH / imageW, 180, 640)`；
  - 优先 `actualParams.size`，其次 `params.size`，auto 按 4:3；
  - 已 resize 的 `canvas.w/h` 优先。
- 自动布局改为行式：每行高度取该行最大节点高度，避免竖图重叠。
- 裁剪、fit、框选、占位块使用同一套动态 rect。
- `CanvasTaskNode` 支持传入 width/height，图片按节点真实比例显示，不变形；compact 低倍节点也使用传入的动态宽高。
- 四角等比 resize：左上/右上/左下/右下四个角点共用一套 pointer 逻辑，按角点方向计算新宽高和 x/y，写入 `canvas.x/y/w/h`。
- 画布框选：工具栏「框选」进入框选模式，拖出矩形后按 `nodeRects` 命中，选中结果接入批量删除。
- 切换画布时清空 `selectedIds`、退出框选模式并清空框选矩形，避免跨画布批量删除。
- 画布节点换 AI Studio 风格：浅/深色 surface、细边框、黑色/白色选中环、玻璃工具条、点阵背景。
- 修复 fit 覆盖用户缩放：fit 只在首次布局执行一次；工具栏缩放/适应全部显式标记为用户操作，任务数组刷新不会再强制拉回「适应全部」。
- 低倍点阵背景最小 16px，避免 3% 缩放时 0.7px 点阵整屏重绘。

### 1.3 性能 / LOD

- 全局缩放 0.02–3.0；fit 可低到 0.02。
- `MAX_RENDER=500` 真实节点；`k < 0.15` 时改用单张 canvas 绘制全部占位块，不再挂载 3000 个 DOM 占位节点。
- 低倍 canvas 每帧只重绘占位矩形，平移时不再进行 DOM 重排；首帧和连续平移都明显快于 DOM 占位方案。
- 视口裁剪 + overscan + compact LOD 保留。

### 1.4 P3 复审非阻塞加固

- 删除画布/项目在最终 remove 前再次保存 live composer，覆盖异步迁移期间的编辑。
- 九宫格底部 padding 增加，避免底部 Dock 遮挡最后一行。

### 2.2 真实 Tauri 性能采样

环境：Windows 11，Tauri dev（WebView2 156），2560×1440；数据为 1000/3000 条合成任务，混合 1:1、3:2、2:3 三种比例；画布为默认项目/默认画布。

采样方法：

- 页面内 dev-only 4 秒连续平移（每帧 x+5px），结束后用 toast 记录 FPS、首帧和占位数量；
- 首帧取 CanvasBoard 首次 effect 的 `performance.now()`（页面导航→画布挂载，不含 Tauri 进程冷启动）；
- 内存取 `Get-Process gpt-image-playground` 的 `WorkingSet64`（主进程，不含 WebView2 子进程）。

结果：

| 场景 | 静止 FPS | 平移 FPS | 节点 | 首帧 | 主进程内存 |
|---|---|---|---|---|---|
| 1000 任务，适应全部 6.4% | 75.0 | **75.2**（301 帧/4s） | 0 真实 + 1000 占位 | 1.63s | 50.8MB |
| 1000 任务，100% | 74.6 | **75.2**（301 帧/4s） | 18 真实 + 0 占位 | — | 50.9MB |
| 3000 任务，适应全部 3.1% | 75.0 | **75.2**（301 帧/4s） | 0 真实 + 3000 画布占位 | 1.62s | 51.8MB |

结论：

- 1000 任务在低倍和 100% 视图下都达到 75fps，满足平移 ≥45fps 的目标。
- 3000 任务低倍改用单张 canvas 绘制占位块后，平移从 24.8fps 提升到 **75.2fps**，首帧从 2.16s 降到 **1.62s**，主进程内存 51.8MB，达到方案要求。
- 开发态 3000 任务 + 右侧历史流展开 + 手动 100% 视图的组合出现过一次 WebView OOM；清理残留 WebView2 进程后按最终默认「首屏 fit 到低倍 + 卡片按需加载图片」复测未再出现。该组合仍需在 P5 做真机长稳验证，并使用系统级内存统计 WebView2 子进程。

## 4. 已知边界

1. 低倍 LOD 下不加载真实节点缩略图；这是 3000 全览的性能取舍。
2. 等比 resize 以拖拽开始时节点比例为准；四角都写入同一套 x/y/w/h。
3. 画布手工摆放节点不参与自动行式重排，只保留 x/y；resize 后 w/h 持久化。
4. 九宫格搜索是当前画布内搜索，符合 §18 决策。
5. 内存采样只统计主进程；WebView2 renderer/GPU 内存未计入，后续可用系统级计数器补。
